# TMAP 搜索执行与索引交集

## 范围

设备搜索遍历安装的地图包，并查询名称／别名索引。不会按当前视野筛选，
也不逐层读取缩放等级或扫描底图。跳转使用结果所在包的可用缩放掩码。
重复 POI 按完整稳定 ID 合并，结果最多保留 24 条；当前排序首先比较距地图
中心的距离，再比较匹配类型、重要性和稳定 ID。显示匹配到的名称／别名及
已写入包中的行政区路径。

## 有序索引交集

子串查询使用已选出的、按数量排序的至多 8 个字符索引列表。列表中的文档
编号严格递增，以最小列表为主列表。旧实现对每个主列表候选反复从头定位
其他列表的分块并二分查找；缓存不能消除这些重复查找本身。

新实现为每个过滤列表保存一个 lower-bound 位置，共增加 64 字节，放在
调用方的 SearchCursor 中；设备调用方使用 PSRAM。游标仍受 1 KiB 静态上限
检查约束，没有新增大型任务栈对象。

对于当前编号 x：

1. 从上次位置检查过滤列表，不向前面的条目回退。
2. 需要继续前进时，以 1、2、4…距离跳跃，找到包围 x 的区间，再在区间内
   二分定位第一个不小于 x 的编号。
3. 若该编号等于 x，继续检查其他过滤列表。
4. 若该编号为 y > x，主列表中所有小于 y 的未处理编号都不在交集中，
   直接把主列表定位到第一个不小于 y 的编号，保留该位置供下一次尝试。
5. 若过滤列表已耗尽，主列表剩余编号也不会匹配，结束当前包的交集。
6. 交集候选仍读取完整规范化名称并检查真实子串，随后读取 POI、匹配名称
   和行政区信息。字符集合匹配不代替完整字符串匹配。

主列表跨度被跳过不代表跳过可能匹配的结果；只跳过已由某个过滤列表证明
不可能匹配的编号。Exact／Prefix 路径继续使用其原有名称字典逻辑。

## Busy 与访问顺序

单个 seek 仅在正常结束时提交新位置。遇到 Busy，当前主候选继续保留；
已成功推进的过滤游标仍是该候选的正确 lower bound，重试无需倒退。
只有名称、POI、匹配显示名称、行政区读取都成功后，才调用结果 visitor。
普通候选完成后推进主位置；范围跳跃保留新的 lower bound，避免再加一而
漏掉区间边界上的匹配。

因此，新增行政区读取遇到 Busy 不会先推进候选并丢失该结果。取消、包构建
标识变化和损坏数据仍遵守既有错误处理。

## 复杂度与调度

单次向前跨越 d 个条目的 seek 约为 O(log(d + 1)) 个值定位。相比每次重新
查完整列表，它利用所有查询编号单调增长这一条件。读取仍经过现有页面
校验和缓存，不把整份索引载入内存。

多个列表按有序 lower bound 交替推进；实际代价取决于列表间距、重叠、
缓存命中及 SD 随机读取。只用逻辑查找次数不能推出设备秒数。

设备目前每批最多尝试 4 个交集候选／推进操作，非 Busy 批次让出执行权
5 ms，Busy 时 20 ms。旧 London 日志中两个包约 7,000 个主候选，逐条处理
仅批次等待就约 9 秒。范围跳过减少批次数，但仍保留调度间隔，不通过持续
抢占 CPU 或 SPI 来换取速度。

日志中的 candidates 位置现在表示主列表处理跨度，包含已证明不匹配而跳过
的部分，不能把它当作实际逐条读取次数。结合 reads、cache_hits、sd_bytes
和总耗时判断效果。当前改动尚未通过设备日志验证实际搜索延迟。

## 字体引用回收保护

字体回收除了检查近期使用帧和主字体身份，还检查字体包装对象的 base 和
explicit_fallback 借用。仍有这类直接引用的字体保持加载，避免其他语言预览
等界面持有已释放的数据。此检查只扫描已有固定绑定池，不新增字库或位图
缓冲；不能为了装入新字库而绕过既有引用保护与 RAM 预算。
