# TMAP 固件读取与接入

## 分支与范围

实现分支为 `feature/tmap-reader`，从拉取后的 `origin/main`（`caef427b`）创建。此版本接入 ESP 地图工作线程、原生瓦片显示和 Arduino ESP32 已有的独立文字标注流程。

原来的地图流程读取单独的 PNG 瓦片和 POI JSONL，没有 TMAP 容器读取能力。本实现新增 TMAP v1 读取核心和地图源。数据源模式在地图运行时初始化时确定：有效包目录非空使用 TMAP；目录不存在或无包时使用旧目录。TMAP 模式的缺失覆盖不会逐块回退到旧文件。

读取器使用 Center 当前输出的实际 profile：小端、4096 字节索引页、WGS84 E7 坐标、名称规范化 profile 2。支持 RGB565LE 和 straight RGBA8888、POI 表、稳定 ID 索引、名称搜索索引、空间索引和独立标注。路网及路径规划不在本次范围内。

## SD 卡布局

将成品直接放到 SD 卡的以下目录，无需拆成小瓦片：

```text
/maps/tmap/
  world-osm-z0-7.tmap
  china-osm-z8-12.tmap
  yunnan-osm-z13-17.tmap   # 示例；需先由 Center 制作
```

固件枚举该目录直接包含的 `.tmap` 文件，扩展名不区分大小写，不递归扫描子目录。世界、中国两个实际成品已经用于读取验证；云南这一行是未来包的布局示例。

中国包约 29.67 GB，必须使用支持该文件大小的文件系统；FAT32 的单文件限制不满足要求。现有 ESP SD 运行时启用了 SdFat FAT/FAT32/exFAT 支持，随机访问接口和本读取器全程使用 64 位偏移。文件系统能够挂载和驱动是否适用于具体硬件，仍需该硬件上的验证。

包的绝对路径最多 191 个 UTF-8 字节，目录最多 256 个有效包。路径过长、超过容量或包损坏会返回错误，不会将不完整目录当作完整地图覆盖使用。建议使用简短的 ASCII 文件名。运行期间原地修改已打开的文件不受支持；更新地图后重新挂载或重启设备，使介质会话和缓存重新建立。

## 多包选择

首次访问时分批建立元数据目录，每次最多读取八个包的头和目录。目录按 16 个条目为一组在 PSRAM 中扩容，所有包复用一个 Reader、一个固定工作区和一个活动包文件。

目录建立完成后固定本次运行时的数据源模式。Busy/More 表示初始化尚未完成，必须等待重试；损坏包或 I/O 错误不允许偷偷切换旧文件。介质会话变化或地图工作线程退出后重建模式。普通拖动、缩放、图层切换不重新选择 TMAP/旧瓦片格式。

排序后预计算 32 个缩放掩码位的候选包位图，共 1024 字节 PSRAM。固定 16 项定位缓存记录瓦片 Morton 键、图层语义、包索引、offset/length/CRC/codec，采用循环替换，包含确定的 Missing 结果；不缓存 Busy 或读取错误。存在性查询和实际读取复用偏移，OSM 与其 POI 请求共用对应底图定位。文件切换仍验证包 build；介质变化清空全部定位结果。

每个瓦片请求的选择顺序：

1. 校验 XYZ 坐标范围。
2. 查固定定位缓存；未命中时，从预计算的当前缩放候选位图中用覆盖范围筛选包。
3. 优先区域精细度较高的包；其次优先较新 revision；再按包 ID 和路径稳定排序。
4. 在候选包对应图层的 B+ 树中查找准确的瓦片键。
5. 优先包缺少该瓦片时，继续较低优先级的 TMAP 候选包；全部包缺少时返回 Missing，不访问旧 PNG 或 JSONL。

视口所需的 N 块瓦片继续通过有界异步队列流式读取，已定位的数据按 64 位 offset 随机访问，不重复查询索引。16 项缓存是定位结果缓存，不是 N 块像素驻留区。当前没有将整个视口按 offset 排序或合并成一个大读操作；保留显示优先级和逐块发布，避免额外 N 块像素缓冲及长时间占用共享 SPI 总线。

世界 0–7、中国 8–12、省级 13–17 因缩放掩码不同可以同时安装，不需要将它们合并成一个超大文件。POI 显示标注使用对应 OSM 瓦片所选的包，通过瓦片标注索引访问，不扫描整个 POI 表。

当前没有让用户选择地图系列的 UI；应安装同一制作系列的区域包，避免重叠包的绘制风格不一致。目录排序只依据上述优先级，不会把不同来源的 POI ID 自动映射成同一个地点。

## 显示与内存所有权

RGB565 瓦片直接建立 LVGL RGB565 图像描述符，跳过 PNG 解码。RGBA 瓦片在 CRC 通过后原地转换为 LVGL 所需的 BGRA 通道顺序，不申请第二份转换缓冲。透明度保持 straight alpha。

地图工作线程使用一个 256 KiB PSRAM 工作缓冲，支持 v1 最大 RGBA 瓦片。读取完成后复制一次到受预算限制的事件缓冲。事件与 LVGL 缓存通过引用计数共用这一份像素；建立显示描述符不会再复制完整像素。

原生像素的队列和显示缓存共享 **3 MiB** 分配预算，包含引用计数头。预算不足时发布可重试事件。该预算不包含工作缓冲、目录、独立标注、其他页面及旧 PNG 解码缓存，因此不能称为整机 PSRAM 上限。大块新分配显式要求 PSRAM，不回退到内部 RAM。

离开地图且没有活动视口后，工作线程释放工作缓冲、包目录及读取工作区。显示缓存是否保留仍遵循已有硬件内存配置；保留的原生像素仍计入预算，缓存淘汰时回收。介质会话改变时重建包目录、清除旧 POI 策略，并在 UI 地图同步时取消旧代请求、重置地图对象和显示缓存。旧会话的缺失记录不阻挡新卡读取。存在性查询和实际读取遵循同一个固定数据源模式；生成的 POI 载荷大小尚未确定时，存在性查询返回 size=0，不用底图像素大小代替。

TMAP 标注的 UI 策略允许请求所有 UI 缩放级别，覆盖由包目录决定，不能把世界包 0–7 的掩码作为整个视口后续的限制。否则切到中国包 8–12 时会停止请求 POI。SD 分片读取中途 Busy 必须保留可重试状态；POI I/O 错误每 5 秒允许重试，不能一次失败后永久标记已检查。缺失与格式错误不进入该重试。

`[GPS][MAP][source-mode]` 在初始化完成时输出 `mode=tmap/legacy`、包数量和介质会话。TMAP 读取日志 `[GPS][MAP][source]` 分底图/标注每组最多每 5 秒一条，输出实际选中的包路径、状态、坐标、字节数及 `fallback_legacy=0`。事件错误日志只输出 `tile_id=图层/z/x/y`，不再生成旧 PNG/JSONL 路径。`progress/-115` 是有进度的分段处理，不是 Busy；`busy/-11` 才表示本次访问暂时未完成。

## 续读、取消与视口预取

像素读取直接写入原有单个 256 KiB PSRAM 工作缓冲，每次最多处理四个 4 KiB 请求。完成一段后返回 More，工作线程保留同一个命令和缓冲，释放事件预留并让出一个 RTOS tick，再继续下一段。Busy 后已读字节不会从头重读，CRC 只在整个瓦片完成后执行。每次续执行前重新检查请求是否已取消。没有第二份完整像素缓冲。

SD 适配器按需分配两个 4 KiB PSRAM 块，保留索引页的分片进度和已完成内容。只有完整内容才复制到读取器，不能让读取器消费 Busy 时的部分输出。顺序位置已正确时不再执行重复 seek；文件切换使块缓存失效，关闭运行时释放这些块。

标注使用 caller-owned AnnotationCursor（编译期上限 1 KiB），将索引定位、标注记录、几何、POI 行、名称行、名称字符串和输出分成独立阶段。Busy 后只重试未完成阶段，游标保存数据而不是借用索引页指针。每段最多 64 个阶段，并在阶段之间检查 20 ms 时间预算；一次底层 SD 操作可能超过该时间，故不是硬实时保证。原有同步 visitAnnotations 接口保留供其他调用方使用。

像素 More 必须保留原命令，保证借用的工作缓冲不被覆盖；标注 More 使用独立 PSRAM 续读槽，可以交付带 `-115` 的重试事件后让下一条底图/预取命令运行。UI 最多保留三个在途 POI 请求，与续读槽数量一致，避免连续处理一整块密集标注阻挡新底图。

地图源最多保存三个标注续读槽，每槽载荷按需分配，仍保留每瓦片最多 200 条标注。完成后把载荷复制到原有事件流程；取消后清空游标状态，重用已分配缓冲，退出地图释放。所有游标和载荷均在 PSRAM，不放在任务栈。

缩放改变时推进地图请求代次，取消旧队列和在途结果，清掉旧 pending 状态；新代的第一个 worker 请求清除旧标注和像素续读状态。读取统计跨续执行累加，排队耗时从第一次开始处理计算，避免把续读时间误计为队列等待。

预取以当前视口的精确瓦片范围加一圈邻域为候选，不再扫描 GPS 周围固定 21×21 网格。只保留最多四个屏外候选，优先滑动方向前方，再按距离排序，并受图像对象缓存空位限制。可见底图未完成时不启动预取，最多一个屏外预取在途；原生像素预算剩余不足两张最大 RGBA 瓦片时暂停预取。

预取像素共用原有 3 MiB 缓存预算，提前建立隐藏图像描述符。拖动时进入屏幕直接显示已有描述符；ESP 拖动期间每个 loader tick 继续做有界视口规划和异步事件应用，UI 不访问 SD。POI 和等高线仍只请求可见区域。普通速度下预取可减少空白，但快速跨区、冷启动、未安装覆盖或 SD 长时间忙时不保证无空白。

`[MapViewport][POI][font] missing_glyph=...` 每 5 秒最多输出一次缺字诊断，区分标注读取成功但字体不能显示的情况。它不会加载整套全球字库，也不改变既有内容字体包的选择与按需加载机制。

详见 [固件资源约束](firmware-resource-budget.md)。

## 读取和查询复杂度

令 F 为已安装包数（F≤256），T 为某层瓦片数，P 为 POI 数，N 为名称数，G 为 gram 种类，q 为查询字符数，D 为驱动倒排的候选名称数，B 为索引页容量。

| 操作 | 算法与复杂度 |
| --- | --- |
| 建立包目录 | O(F) 文件头/目录读取，随后 O(F log F) 元数据排序 |
| 多包选择 | 固定 16 项定位缓存命中为 O(1)；未命中遍历 8 个位图字和当前缩放候选 Fz，O(8+Fz)，最坏 Fz=F；每个候选内部查找 O(log_B T) |
| 单包瓦片定位 | O(log_B T) 页查找，之后固定 128 / 256 KiB 像素读取和 CRC |
| POI 行号读取 | O(1) 行地址计算，名称按字符串引用读取 |
| 稳定 ID 查找 | O(log_B P) + POI 行读取 |
| 精确名称 | O(log_B N + 命中数) 索引访问 |
| 前缀名称 | O(log_B N + 遍历名称项 + 倒排候选数)，通过叶链访问 |
| 片段名称 | O(q log_B G) 初始化；取最多八个稀有 gram，以最短倒排驱动，其他列表按块和块内二分探测；每个候选再核对完整规范化名称 |
| 按瓦片读标注 | O(log_B T + J)，J≤200，且回调输出受调用方容量限制 |
| 空间范围 | R-tree 包围盒剪枝；最坏 O(P)，不是无条件的 O(log P) |

搜索核心提供 `beginSearch` 和 `searchStep`，初始化不执行 SD 读取，后续每批最多消耗 64 个初始化索引项或候选名称。`More` 表示需续执行，`Busy` 表示重试当前步骤，回调返回 false 可停止。短前缀、单字查询可能存在大量候选，返回少量结果并不意味着只访问少量候选。

名称规范化遵循制作端 profile 2：全角 ASCII 转半角、ASCII 小写化和显式空白规范化，保留其他 Unicode 字符；没有额外实现拼音索引、简繁转换或完整 Unicode case folding。

此版本实现搜索读取 API，**尚未新增设备搜索输入框、多包 Top-K 搜索调度或路径导航 UI**。保留搜索结果的调用方必须复制借用的数据并按完整 128 位稳定 ID 去重，不能只使用标注显示中的 64 位哈希。

## 验证入口

- `tests/tmap/probe.cpp`：对实际包验证像素 CRC、64 位偏移、POI 稳定 ID、标注和名称搜索。
- `tests/tmap/source_probe.cpp`：实际世界/中国包组合的地图源选择、复用、标注适配、Busy 重试、介质切换、分配失败和像素引用预算。
- `tests/map_tile_image/test_native_image.cpp`：使用固定 LVGL 9.4.0 渲染 RGB565/RGBA，验证描述符共用原像素、分配失败以及最后一次引用释放。
- `tests/map_tile_pipeline`：原有异步队列、请求、取消、POI 重试和目录瓦片读取回归。

独立实包验证可执行：

```text
tmap_probe <world.tmap> 7 116.4 39.9
tmap_probe <china.tmap> 12 102.7 25.04
tmap_source_probe <world.tmap> <china.tmap>
```

实际中国包验证读取了 `12/3216/1753`，像素位于文件 21,634,830,336 字节偏移，CRC32C 为 `a4e01293`；世界包 `7/105/48` CRC32C 为 `3ef54c05`。这些是文件和显示后端兼容性证据，不等同于 SD 卡、SPI、PSRAM、屏幕和任务栈的整机验收。
