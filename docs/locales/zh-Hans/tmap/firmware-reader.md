# TMAP 固件读取与接入

## 分支与范围

实现分支为 `feature/tmap-reader`，从拉取后的 `origin/main`（`caef427b`）创建。此版本接入 ESP 地图工作线程、原生瓦片显示和 Arduino ESP32 已有的独立文字标注流程。

原来的地图流程读取单独的 PNG 瓦片和 POI JSONL，没有 TMAP 容器读取能力。本实现新增 TMAP v1 读取核心和地图源。数据源模式在地图运行时初始化时确定：有效包目录非空使用 TMAP；目录不存在或无包时使用旧目录。TMAP 模式的缺失覆盖不会逐块回退到旧文件。

读取器使用 Center 当前输出的实际 profile：小端、4096 字节索引页、WGS84 E7 坐标、名称规范化 profile 2。支持 RGB565LE 和 straight RGBA8888、POI 表、稳定 ID 索引、名称搜索索引、空间索引和独立标注。路网及路径规划不在本次范围内。

## SD 卡布局

将成品直接放到 SD 卡的以下目录，无需拆成小瓦片：

```text
/maps/tmap/
  osm/
    world-osm-z0-7.tmap
    china-osm-z8-12.tmap
    yunnan-osm-z13-17.tmap   # 示例；需先由 Center 制作
  terrain/
    china-terrain-z8-12.tmap # 示例
  satellite/
    china-satellite-z8-12.tmap # 示例
```

固件依次枚举上述三个固定子目录，并兼容旧的 `/maps/tmap` 平铺目录。扩展名不区分大小写，不递归扫描任意子目录。目录名用于整理；实际图层类型由包内图层语义决定。每次最多检查 32 个目录项，目录切换保持有界。世界、中国 OSM 包已实际制作；其余行是布局示例。

中国包约 29.67 GB，必须使用支持该文件大小的文件系统；FAT32 的单文件限制不满足要求。现有 ESP SD 运行时启用了 SdFat FAT/FAT32/exFAT 支持，随机访问接口和本读取器全程使用 64 位偏移。文件系统能够挂载和驱动是否适用于具体硬件，仍需该硬件上的验证。

包的绝对路径最多 191 个 UTF-8 字节，目录最多 256 个有效包。路径过长、超过容量或包损坏会返回错误，不会将不完整目录当作完整地图覆盖使用。建议使用简短的 ASCII 文件名。运行期间原地修改已打开的文件不受支持；更新地图后重新挂载或重启设备，使介质会话和缓存重新建立。

## 多包选择

首次访问时分批建立元数据目录，每次最多读取八个包的头和目录。目录按 16 个条目为一组在 PSRAM 中扩容，所有包复用一个 Reader、一个固定工作区和一个活动包文件。

目录建立完成后固定本次运行时的数据源模式。Busy/More 表示初始化尚未完成，必须等待重试；损坏包或 I/O 错误不允许偷偷切换旧文件。介质会话变化或地图工作线程退出后重建模式。普通拖动、缩放、图层切换不重新选择 TMAP/旧瓦片格式。

排序后预计算 32 个缩放掩码位的候选包位图，共 1024 字节 PSRAM。固定 16 项定位缓存记录瓦片 Morton 键、图层语义、包索引、offset/length/CRC/codec，采用循环替换，包含确定的 Missing 结果；不缓存 Busy 或读取错误。存在性查询和实际读取复用定位；POI 使用独立标注键，不依赖 OSM 像素存在。文件切换仍验证包 build；介质变化清空全部定位结果。

每个瓦片请求的选择顺序：

1. 校验 XYZ 坐标范围。
2. 查固定定位缓存；未命中时，从预计算的当前缩放候选位图中用覆盖范围筛选包。
3. 优先区域精细度较高的包；其次优先较新 revision；再按包 ID 和路径稳定排序。
4. 在候选包对应图层的 B+ 树中查找准确的瓦片键。
5. 优先包缺少该瓦片时，继续较低优先级的 TMAP 候选包；全部包缺少时返回 Missing，不访问旧 PNG 或 JSONL。

视口所需的 N 块瓦片继续通过有界异步队列流式读取，已定位的数据按 64 位 offset 随机访问，不重复查询索引。16 项缓存是定位结果缓存，不是 N 块像素驻留区。当前没有将整个视口按 offset 排序或合并成一个大读操作；保留显示优先级和逐块发布，避免额外 N 块像素缓冲及长时间占用共享 SPI 总线。

世界 0–7、中国 8–12、省级 13–17 因缩放掩码不同可以同时安装，不需要将它们合并成一个超大文件。POI 显示通过独立瓦片标注索引选包，不扫描整个 POI 表；可以由只有 POI/搜索/标注的包为卫星或地形底图提供文字。

当前没有让用户选择地图系列的 UI；应安装同一制作系列的区域包，避免重叠包的绘制风格不一致。目录排序只依据上述优先级，不会把不同来源的 POI ID 自动映射成同一个地点。

## 显示与内存所有权

RGB565 瓦片直接建立 LVGL RGB565 图像描述符，跳过 PNG 解码。RGBA 瓦片在 CRC 通过后原地转换为 LVGL 所需的 BGRA 通道顺序，不申请第二份转换缓冲。透明度保持 straight alpha。

地图工作线程使用一个 256 KiB PSRAM 工作缓冲，支持 v1 最大 RGBA 瓦片。读取完成后复制一次到受预算限制的事件缓冲。事件与 LVGL 缓存通过引用计数共用这一份像素；建立显示描述符不会再复制完整像素。

原生像素的队列和显示缓存共享 **3 MiB** 分配预算，包含引用计数头。预算不足时发布可重试事件。该预算不包含工作缓冲、目录、独立标注、其他页面及旧 PNG 解码缓存，因此不能称为整机 PSRAM 上限。大块新分配显式要求 PSRAM，不回退到内部 RAM。

离开地图且没有活动视口后，工作线程释放工作缓冲、包目录及读取工作区。显示缓存是否保留仍遵循已有硬件内存配置；保留的原生像素仍计入预算，缓存淘汰时回收。介质会话改变时重建包目录、清除旧 POI 策略，并在 UI 地图同步时取消旧代请求、重置地图对象和显示缓存。旧会话的缺失记录不阻挡新卡读取。存在性查询和实际读取遵循同一个固定数据源模式；生成的 POI 载荷大小尚未确定时，存在性查询返回 size=0，不用底图像素大小代替。

TMAP 标注的 UI 策略允许请求所有 UI 缩放级别，覆盖由包目录决定，不能把世界包 0–7 的掩码作为整个视口后续的限制。否则切到中国包 8–12 时会停止请求 POI。SD 分片读取中途 Busy 必须保留可重试状态；POI I/O 错误每 5 秒允许重试，不能一次失败后永久标记已检查。缺失与格式错误不进入该重试。

`[GPS][MAP][source-mode]` 在初始化完成时输出 `mode=tmap/legacy`、包数量和介质会话。TMAP 读取日志 `[GPS][MAP][source]` 分底图/标注每组最多每 5 秒一条，输出实际选中的包路径、状态、坐标、字节数及 `fallback_legacy=0`。事件错误日志只输出 `tile_id=图层/z/x/y`，不再生成旧 PNG/JSONL 路径。`progress/-115` 是有进度的分段处理，不是 Busy；`busy/-11` 才表示本次访问暂时未完成。

## 续读、取消与视口预取

像素读取直接写入原有单个 256 KiB PSRAM 工作缓冲，每次最多处理四个 4 KiB 请求。完成一段后返回 More，工作线程保留同一个命令和缓冲，释放事件预留并让出一个 RTOS tick，再继续下一段。Busy 后已读字节不会从头重读，CRC 只在整个瓦片完成后执行。每次续执行前重新检查请求是否已取消。没有第二份完整像素缓冲。

SD 适配器按需分配两个 4 KiB PSRAM 块，保留索引页的分片进度和已完成内容。只有完整内容才复制到读取器，不能让读取器消费 Busy 时的部分输出。顺序位置已正确时不再执行重复 seek；文件切换使块缓存失效，关闭运行时释放这些块。

标注使用 caller-owned AnnotationCursor（编译期上限 1 KiB），将索引定位、标注记录、几何、POI 行、名称行、名称字符串和输出分成独立阶段。Busy 后只重试未完成阶段，游标保存数据而不是借用索引页指针。每段最多 64 个阶段，并在阶段之间检查 20 ms 时间预算；一次底层 SD 操作可能超过该时间，故不是硬实时保证。原有同步 visitAnnotations 接口保留供其他调用方使用。

像素 More 必须保留原命令，保证借用的工作缓冲不被覆盖；标注 More 使用独立 PSRAM 续读槽，短段在 worker 内继续执行，累计约 100 ms 后交付带 `-115` 的重试事件以允许底图/预取运行，部分快照也结束当前请求。UI 最多保留三个在途 POI 请求，与续读槽数量一致。

像素续读所有者由请求代次和 command ID 共同确定。新命令开始即丢弃旧像素进度，即使坐标或缩放相同；只有同一命令的 Yielded 才能继续借用缓冲。已有像素续读遇到 USB/介质暂时占用时保持 More，不发布会允许其他命令覆盖缓冲的 Busy 事件；不可重试错误清除像素进度。

地图源最多保存三个标注续读槽，每槽载荷按需分配，仍保留每瓦片最多 200 条标注。完成后把载荷复制到原有事件流程；取消后清空游标状态，重用已分配缓冲，退出地图释放。所有游标和载荷均在 PSRAM，不放在任务栈。

标注不等待整个瓦片完成才显示：第一条完整标注立即发布有效快照，随后每新增四条或有新增记录且距上次发布达到一秒时合并发布。内存 TileHeader.partial 标明快照尚未完成（不改变 TMAP 文件格式）；UI 显示已读数据并继续请求剩余部分。完成快照清掉 partial，停止续读请求。该策略避免在频繁缩放时一直没有文字，并限制快照复制和布局频率。

More/-115 和 partial 快照不执行 Busy 的 900 ms 退避，允许下个 loader tick 继续。三个续读槽满时对新瓦片返回准入背压，绝不替换尚未完成的游标；否则瓦片数量超过三个时会循环重启标注。视口任一边界的瓦片范围改变时推进请求代次并取消旧任务，释放不再需要的槽；同一瓦片范围内的普通像素移动不取消进度。

`[TMAP][POI][progress]` 每五秒记录一次阶段、已处理/预期记录数和当前载荷记录数；`[MapViewport][POI]` 同时打印 partial，区分增量显示与最终完成。progress 日志可用于确认游标是否持续前进，不只根据 -115 判断。

缩放改变时推进地图请求代次，取消旧队列和在途结果，清掉旧 pending 状态；新代的第一个 worker 请求清除旧标注和像素续读状态。读取统计跨续执行累加，排队耗时从第一次开始处理计算，避免把续读时间误计为队列等待。

预取以当前视口的精确瓦片范围加一圈邻域为候选，不再扫描 GPS 周围固定 21×21 网格。只保留最多四个屏外候选，优先滑动方向前方，再按距离排序，并受图像对象缓存空位限制。可见底图未完成时不启动预取，最多一个屏外预取在途；原生像素预算剩余不足两张最大 RGBA 瓦片时暂停预取。

预取像素共用原有 3 MiB 缓存预算，提前建立隐藏图像描述符。拖动时进入屏幕直接显示已有描述符；ESP 拖动期间每个 loader tick 继续做有界视口规划和异步事件应用，UI 不访问 SD。POI 和等高线仍只请求可见区域。普通速度下预取可减少空白，但快速跨区、冷启动、未安装覆盖或 SD 长时间忙时不保证无空白。

`[MapViewport][POI][font] missing_glyph=...` 每 5 秒最多输出一次缺字诊断，区分标注读取成功但字体不能显示的情况。它不会加载整套全球字库，也不改变既有内容字体包的选择与按需加载机制。

详见 [固件资源约束](firmware-resource-budget.md)。

## 读取和查询复杂度

令 F 为已安装包数（F≤256），T 为某层瓦片数，P 为 POI 数，N 为名称数，G 为 gram 种类，q 为查询字符数，D 为驱动倒排的候选名称数，B 为索引页容量。

| 操作 | 算法与复杂度 |
| --- | --- |
| 建立包目录 | O(F) 文件头/目录读取，随后 O(F log F) 元数据排序 |
| 多包选择 | 固定 16 项定位缓存命中为 O(1)；未命中遍历 8 个位图字和当前缩放候选 Fz，O(8+Fz)，最坏 Fz=F；每个候选内部查找 O(log_B T) |
| 单包瓦片定位 | O(log_B T) 页查找，之后固定 128 / 256 KiB 像素读取和 CRC |
| POI 行号读取 | O(1) 行地址计算，名称按字符串引用读取 |
| 稳定 ID 查找 | O(log_B P) + POI 行读取 |
| 精确名称 | O(log_B N + 命中数) 索引访问 |
| 前缀名称 | O(log_B N + 遍历名称项 + 倒排候选数)，通过叶链访问 |
| 片段名称 | O(q log_B G) 初始化；取最多八个稀有 gram，以最短倒排驱动，其他列表按块和块内二分探测；每个候选再核对完整规范化名称 |
| 按瓦片读标注 | O(log_B T + J)，J≤200，且回调输出受调用方容量限制 |
| 空间范围 | R-tree 包围盒剪枝；最坏 O(P)，不是无条件的 O(log P) |

搜索核心提供 `beginSearch` 和 `searchStep`，初始化不执行 SD 读取，后续每批最多消耗 64 个初始化索引项或候选名称。`More` 表示需续执行，`Busy` 表示重试当前步骤，回调返回 false 可停止。短前缀、单字查询可能存在大量候选，返回少量结果并不意味着只访问少量候选。

名称规范化遵循制作端 profile 2：全角 ASCII 转半角、ASCII 小写化和显式空白规范化，保留其他 Unicode 字符；没有额外实现拼音索引、简繁转换或完整 Unicode case folding。

此版本实现搜索读取 API，**尚未新增设备搜索输入框、多包 Top-K 搜索调度或路径导航 UI**。保留搜索结果的调用方必须复制借用的数据并按完整 128 位稳定 ID 去重，不能只使用标注显示中的 64 位哈希。

## 大文件随机定位与连续读取（2026-10-10）

TMAP 索引的 offset 定位不等于文件系统的常数时间定位。非连续 exFAT
文件向后 seek 时，SdFat 会从首簇重新遍历簇链；索引、像素与标注交替读取，
可能让大型地图重复承担这一成本。连续文件或已命中的像素缓存不一定有此开销。

只读 `.tmap` 句柄现在按需分配 64 项文件位置缓存，严格使用 PSRAM。
每项保存 SdFat 自身返回的文件位置及簇游标，选择不超过目标的最近已知前驱，
再调用原有 seek；失败时恢复原来的位置。关闭文件释放缓存，介质失效后禁止使用。
分配失败保持原定位路径，不回退到内部 RAM。

32 项保存沿首次前向读取逐步建立的等间隔位置，另外 32 项保存最近访问位置。
间隔为文件长度的约 1/32，向上取整到 MiB；首次远距离定位沿途保存游标，不在打开
文件时进行完整扫描。固定位置不会被近期页访问挤掉，也有助于持续反向平移。

缓存选择为 O(64)，后续遍历为 O(D)，D 为前驱与目标之间的簇数。
冷读、未缓存区域和严重碎片仍可能遍历长簇链；不能声称所有读取都达到 O(1)。
普通文件和可写句柄不建立这个缓存。

TMAP 小页缓存从 2 页增为 8 页，增加约 24 KiB PSRAM。
索引/标注页按完整剩余页请求，而不是在适配器中反复请求 512 字节；底层共享
SPI 的物理切片和总线策略保留。SDMMC 像素每轮最多请求 32 KiB，然后交还执行权，
复用原有 PSRAM 像素缓冲，内部 DMA 缓冲仍为 4 KiB。

`[TMAP][SD][seek]` 输出定位次数、恢复游标次数、平均/最大定位耗时及缓存字节数。
与 `[GPS][MAP][perf]` 一起判断定位、读取和排队开销。代码修改与构建成功不能替代
真机速度比较，需使用相同区域、缩放、SD 卡和操作节奏比较冷读与重复访问。

## 图层目录与完成结果接收（2026-10-10）

建立包目录时读取每包的图层表，缓存 13 个语义图层各自的缩放位图，以及是否存在
POI 行。包条目增加约 56 字节，按原有分块目录分配在 PSRAM；不新增像素副本。
选包先按实际图层/缩放与区域筛选，再打开文件。无 POI 的地形或卫星包不会参与标注
查找。图层筛选 O(1)，未命中定位缓存时整体仍为 O(8+Fz)，不会声称跨包查询 O(1)。
读取图层表的 Busy 不发布半成品目录，后续可重试。目录更新仍受介质 session 约束。

`[TMAP][PACKAGE] activate path=... switches=...` 按限频规则记录实际包切换，
用于检查同一区域/同一图层请求是否无效切换；合法的区域或样式切换仍会发生。

原生像素与 POI 每轮最多接收 4 个完成结果，每轮预算仍为 4 ms；单个结果应用结束后
检查时间，所以不是任务抢占式的严格 4 ms 上限。PNG 每轮最多处理一次，并保留原有
60 ms 冷却。原生像素/POI 可以绕过 PNG 的冷却，不承担解码等待。

Arduino ESP 的地图页面增加 30 ms UI 侧完成检查。队列为空或互斥锁忙时立即返回，
不访问 SD、不做地图规划、不刷新画面；有完成结果才调用预算受限的 loader。
原有视野规划定时器不变。此检查仍是轻量轮询，并非工作线程直接唤醒 LVGL；
UI 忙碌时不保证在 30 ms 内显示。检查器随页面销毁释放，其他平台不新增该定时器。

## 减少重复工作与 scratch（2026-10-10）

- POI 保留第一批预览和最终完整结果；后续新增记录达到至少 16 条且约半块标注，
  或有新增记录且距上次发布一秒时，再发布阶段结果。阶段结果仍含完整已读前缀。
  不新增队列或缓冲，也不丢弃请求完成事件；一块地图仍最多有一个 pending 请求。
- 布局先在原候选数组上原地堆排序，再按原有类别配额顺序扫描。排序与候选选择
  从最坏 O(C²) 降至 O(C log C)，不用第二份数组、不递归。文字碰撞、历史保留与
  道路放置仍有各自成本，不能声称整体布局复杂度都降到 O(C log C)。
  原始顺序编号使用候选结构现有尾部空隙，处理完有名称候选后原地恢复数组及输出
  索引，保留无名称标记的原聚合顺序。编译期检查保证候选存储不增长。
- 一轮完成结果应用后统一更新底图渲染队列；没有底图状态变化时不重建。只用于
  关闭的详细日志的可见块统计也不再计算。POI revision/字体签名的布局去重继续保留。
- TMAP 原生像素直接读入受预算约束的 NativePixelBuffer。CRC 成功后，完成队列
  持有一个引用，LVGL 再借用同一缓冲；不再复制完整像素到第二份事件缓冲。
  worker 在终态发布后释放自己的引用，取消、失败和介质变化也会释放在读引用。
- 原 3 MiB 像素预算现在同时包含在读、排队及已显示缓冲，不能把新的 native 统计
  与此前只包含排队/显示的数值直接比较。预算和像素质量/CRC 没有放宽。
- TMAP 模式确定后，在命令终态释放 256 KiB 通用 scratch，下一次按需分配 48 KiB，
  仍严格使用 PSRAM，减少 212,992 字节（208 KiB）。编译期检查保证能放下最大 POI
  结果。旧 PNG 模式保留 256 KiB；介质切换回旧模式时可恢复。分配失败按资源忙重试。
- 原生所有权标记放在事件的现有对齐空隙，编译期检查保证不移动 payload。
  新增少量后端指针/长度元数据，整体 PSRAM 节省仍约 208 KiB；不是每个字段都零增量。
- 命令队列有积压时，命令间等待由 32 ms 改为一个 RTOS tick；没有积压时保留原等待。
  读取批次和命令之间仍让出执行权，不提升任务优先级，不新增线程。
  这会改变短时活跃度，不能据此宣称功耗或其他任务延迟已经下降。

新日志 `[GPS][MAP][worker] scratch_bytes=49152 saved_psram_bytes=212992 native_direct=1`
确认进入小 scratch 模式；实际 PSRAM、任务栈及速度仍需真机日志验证。

本轮 Wio L2 构建成功：静态 RAM 仍为 99,200 字节，Flash 为 4,480,601 字节，
较上一版增加 1,924 字节代码。208 KiB 是 scratch 分配差值，不是整机峰值的实测
差值；在读缓冲、字体、屏幕状态及少量元数据都会影响真机的可用 PSRAM。

## 底图与 OSM 标注交替读取（2026-10-10）

Arduino ESP 地图存储在目录初始化完成后启用最多两个保留文件的 MRU 策略。
同一个文件不重复打开；交替访问两个包时，交换当前/保留文件及其位置状态，
每个 SdRuntimeFile 自己保留 FAT 簇游标缓存。第三个包替换最近最少使用的文件。
Reader 的包头仍在切换时验证，build 校验仍保留；没有增加第二份 Reader workspace。
两个句柄共享原有八个 4 KiB 小页，每页同时匹配文件对象身份、偏移和长度。
句柄重新打开前只使属于该对象的页失效，避免跨文件、跨版本误命中。
可选搜索缓存切换文件时继续清空；搜索实例不启用双文件策略。

保留状态按需分配在 PSRAM，失败保持原单文件读取。额外资源包括一个小文件状态、
一个 SdRuntimeFile 实现及其约 1,560 字节的 PSRAM seek 缓存，以及每页的文件身份字段。
文件实现沿用底层 PSRAM 优先分配策略，不能宣称完全没有运行时内部 RAM 增量。
不增加 32 KiB 数据页副本、像素预算、48 KiB scratch 或线程。状态切换为固定大小
O(1)，共享页查找为 O(8)；冷 seek 仍可能遍历 FAT 簇链。
关闭地图读取器或更换介质会关闭两个文件并释放保留状态、seek 缓存及共享页。

仅修改底图/等高线选项时，重置像素和等高线，保留现有瓦片记录中的完整 OSM 标注。
取消旧代次 pending 请求，未完成标注由新代次继续请求；介质变化仍清空全部记录。
不扩大 POI 缓存范围，原不可见瓦片回收规则继续生效。

`[TMAP][SD][pair] opens=... resumes=... extra_state_bytes=... shared_pages=8`
记录实际打开和保留文件恢复次数。`[TMAP][PACKAGE] switches` 仍表示 Reader 选包次数，
不能把它当成实际文件打开次数。真机应分别比较冷加载、同位置样式切换和持续平移；
代码与构建不能证明具体提速比例。
