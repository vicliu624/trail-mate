# TMAP 地点文字字库

## 导出要求

TMAP 中的 UTF-8 地点名称不包含字形。Center 必须在生成含 POI 的地图包时，
收集地点名称、搜索别名和已生成的行政区路径所需字符，生成配套字库。
只有生成地图文件而未生成、安装字库，无法保证设备显示这些名称。

目前 Center 的 TMAP 构建默认启用字库生成。地图导出器先发布字体资源，
再发布对应地图文件。字体使用 16 px、2 bpp 的 LVGL 二进制格式，以内容哈希
作为资源 ID；不同地图可复用相同资源。

## SD 卡目录

```text
/maps/tmap/osm/world-osm-z0-7.tmap
/maps/tmap/osm/china-osm-z8-12.tmap
/trailmate/packs/fonts/<resource-id>/manifest.ini
/trailmate/packs/fonts/<resource-id>/font.bin
/trailmate/packs/fonts/<resource-id>/ranges.txt
```

每个字体目录还包含源字体许可和来源哈希。只复制 `.tmap` 不等于安装完成。
字体文件在 TMAP 外部存放，便于共享并使用现有字体加载机制；地图内部保存依赖。

## 文件内依赖结构

可选 section 52 为固定 64 字节的字体依赖记录；section 53 为分页字符串池。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | section 53 内的资源 ID 字符串引用 |
| 8 | 32 | font.bin 的 SHA-256 |
| 40 | 4 | 字形数量 |
| 44 | 4 | 预计加载 RAM 字节数 |
| 48 | 8 | 字体文件字节数 |
| 56 | 2 | 字号，当前为 16 px |
| 58 | 1 | 位深，当前为 2 bpp |
| 59 | 5 | 保留，必须为零 |

以上整数均为小端。依赖表定长记录定位为 O(1)，不需要扫描 POI。
旧包没有依赖段时仍可读取，但不能据此断言字体覆盖完整。

## 生成算法与资源

设名称、别名、行政区路径的总字符数为 C，不同所需字符数为 U。
一次遍历加哈希集合收集的期望时间为 O(C)，集合内存为 O(U)；
排序为 O(U log U)。字体覆盖检查和栅格化在电脑完成，设备无需读取源字体。

生成时按汉字与其他文字分组，每个字体最多包含 2,048 个所需字符，
另加入省略号。每个资源记录自己的 RAM 估计，并设生成阶段容量上限。
此上限不代表设备应同时加载所有资源；设备字体缓存的总预算和 PSRAM
分配仍需要单独遵守。

## 缺字处理与当前产物状态

源字体缺少任何所需字形时，导出报错并生成 `missing-map-glyphs.json`，
列出 Unicode 码点；不把缺字当作成功。私用区字符没有通用字形定义，
必须追查原始名称或指定来源，不能任意绘制替代字形。

2026-10-09 补充 Jigmo、Jomolhari 和单色 Noto Emoji 后，对现有世界包的
实际生成覆盖 3,476 个非 ASCII 字符，生成两个字体文件，分别为 66,800 和
132,268 字节。中国包覆盖 6,622 个非 ASCII 字符，生成四个字体文件，
合计 454,265 字节；此前报告的 39 个缺字已通过补充源字体解决。
源字体留在电脑上，设备只安装生成的裁剪字库。
上述产物仅在电脑生成，尚未据此验证
设备上的字体加载、所有文字的排版或完整安装流程。

当前 standard 设备配置的补充字体缓存最多容纳 2 个包、合计 640 KiB。
原有语言字体可能已占满包数量，因此必须继续处理设备侧的字体选择和
缓存；不能仅凭字库生成成功就认为所有名称已经可以显示。

## 旧地图包的增量安装

Center 的 `extensions-install` 命令接收准备好的地图、设备上的旧地图路径，
以及可选的字体暂存 SD 根目录。它要求旧地图的长度和前 8 KiB 与准备阶段
记录的基准版本完全一致，只传输新增扩展数据，不重传底图。
字体先通过大小、SHA-256 和清单检查并安装，再复制地图尾部并读取校验；
完成后才发布新目录。中断或错误时使用保存的原始长度和头部恢复旧版本。
该路径需在实际设备 USB 存储上验证，不能仅以编译通过作为安装成功证据。
