# Map 中的 TMAP POI 搜索

## 操作流程

Map 底栏的 `F` 按钮或地图界面键盘 `F` 打开 Search 窗口；`W/A/S/D` 保持地图移动。在搜索输入框中输入 `f`、`s` 仍为文字，不触发地图操作。输入地点名称后点击 Search，窗口显示后台查询状态和结果列表。支持现有英文/中文输入法；触摸输入复用已有编辑器。选择结果后关闭窗口，将地图中心跳到结果的 WGS84 坐标。

搜索窗口使用完全不透明的浅色背景，遮挡底图。结果名称使用内容字体通道，按需加载中文核心/扩展字体，并在延迟字体加载后刷新可见名称。每项显示地点名称和距打开窗口时地图中心的距离，分页显示当前页数，不在列表中展示经纬度。

所有页面和主菜单的 topbar 统一使用共享的 24 px 高度，地图底栏仍为 24 px。共享页头使用紧凑字号、padding 和返回按钮；计算器、频谱探测的独立布局也同步该高度。Contour 按钮显示为 `Ctr`，开启时为 `Ctr*`，宽 36 px；固定底栏含边距与间距约 310 px，可容纳在 T-Deck/Wio L2 的 320 px 宽度内。额外路线、队友控件超过可用宽度时底栏可横向滚动，不增加高度。

当前生成的世界/中国包没有每个 POI 的国家、省、市、区县归属关系，暂不能准确展示行政层级；距离是明确的回退信息。完整行政层级需要 Center 将行政边界归属预计算后写入 TMAP，并由设备读取，不能将最近的城市名称当作行政归属。该处理应在制包端进行，避免在设备上扫描边界或进行多边形归属计算。

查询所有安装在 `/maps/tmap/osm`、`terrain`、`satellite` 与旧平铺目录中的可搜索 TMAP，独立于当前视野与缩放。无 POI 数据的包跳过；不访问旧 POI JSON。数据的覆盖与完整性仍由已经生成的地图包决定。

匹配名称与别名的包含索引，同时区分精确、前缀、包含匹配。结果先按匹配级别，再按距离当前视图中心及重要度排序。同一 stable POI ID 去重；相同地点来自多个包时优先保留匹配级别相同、支持更高缩放的版本。

结果池最多 24 条，窗口每页 6 条，列表可滚动，左右分页按钮切换页。超过容量时明确提示收窄名称；不宣称展示了全部匹配。选择结果时将缩放限制在来源包的范围内，避免从高缩放视图跳到只有世界概览包的地区后空白。地图模型保存 WGS84，坐标显示转换由现有视图执行一次。

## 后台任务与资源

- UI 不执行 SD 或 TMAP 索引 I/O。后台搜索任务按每次 4 个候选推进，每批主动让出 CPU，结果每 250 ms 发布一次；界面以 150 ms 定时器取快照。
- `tmap::Workspace`、`SearchCursor`、查询缓冲、工作/发布结果数组、SD 页缓存，以及搜索窗口状态均位于 PSRAM；ESP 没有内部 RAM 缓冲回退。
- 查询时才启动一个 4096 字节内部栈任务，完成或取消后退出。控制对象和信号量为固定小开销。第一次打开前不加载整个地图或搜索索引。
- 只创建 6 个结果行控件，分页复用；搜索输入最多 48 个 Unicode 字符，查询缓冲为 193 字节；结果名为 160 字节并按 UTF-8 边界截断，完整名称索引不受显示上限影响。
- 取消/重搜通过代次隔离旧结果。退出 Map 关闭窗口、停止定时器并请求取消后台任务，工作线程不持有 LVGL 控件。
- 媒体会话变化会终止当前查询，持续 SD Busy 超过 30 秒显示错误；坏包不阻止其他包查询，但结果状态明确标记不完整。包枚举上限 256，超过上限报错而非静默漏搜。
- 目前后台 SD 搜索适配器接入 ESP32 Arduino。其他平台保留共享窗口接口，但尚无该适配器时显示不可用。

## 复杂度

对包 p，包含匹配先查 Unicode n-gram 的 B+ 树索引，并选稀疏 posting 作为候选。设 Np 为名称数、Kp 为候选数、G 为最多 8 个 posting 过滤条件，候选检查受原有 Reader 的索引与 posting 二分查询约束，不扫描底图像素。结果保留成本为 O(Kp × R)，R 固定为 24；单次发布排序 O(R²)，UI 每次更新 O(6)。

总查询会遍历安装包并处理所有索引候选，以保留全局最佳结果。宽泛的单字查询仍可能产生大量候选并花费较长时间；固定缓冲只限制内存，不把查询完整性伪装成固定时间保证。界面保持可关闭、可重搜。

日志 `[TMAP][SEARCH] submit` 包括代次、查询字节数和 PSRAM 状态大小；完成日志包括包数、结果数、容量限制及不完整标志。实际操作与硬件日志验证应在编译、烧录完成后进行。
