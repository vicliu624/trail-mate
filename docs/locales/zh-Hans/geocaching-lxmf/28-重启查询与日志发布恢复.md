# 重启查询与日志发布恢复

## 设备查询恢复

新的浏览会话会生成新的请求 ID，不会重新接管旧页面的请求 ID。旧的持久浏览任务若仍允许继续，派发器可能先重发它们，目录则按幂等约定返回旧响应；新页面无法接受该响应，表现为持续检查目录能力或更新。

Superseded by the [RAM browse runtime](../../../geocaching-client-runtime.md): browsing no longer creates persistent tasks. The dispatcher skips legacy kind-3 tasks without rewriting them at startup. Saved downloads, publications and GPX files retain their durable recovery path.

目录路径响应可能复用之前已接收的公告。活动 Geocaching 会话允许这种路径响应在发现预算内重新验签；经过验签和目的地址绑定检查的相同公告可重新交给目录发现。路由层对过期路径的拒绝仍然有效，不因此替换路径。

## 日志提交边界

事务先写入 `.state/journal.pending`，刷盘、关闭并读回核验后，才通过公共 SD runtime 重命名为 `journal/<sequence>.gcj`。只有正式日志参与恢复和索引引用。单一存储 owner 串行写入；未发布的暂存文件不属于已提交历史，可以由下一次事务覆盖。

这样，写入开始或中途断电不会把空文件或半条事务放入正式日志目录。发布后、索引提交前断电仍由既有日志重放恢复。此调整不会忽略旧版本已经产生的损坏正式日志，也不把 I/O 故障解释为空数据。

## 验证范围

- `geocaching_browse_runtime` now verifies SD-free browsing, abandoned request IDs, bounded retries, and saved download/publication recovery. `geocaching_journal_replay` verifies that legacy browse tasks are not dispatched.
- `geocaching_sd_journal` 在日志写入的每个步骤后中断，验证正式日志不存在或与完整预期逐字节一致，随后验证可重试且不覆盖已发布日志；保留每步最多一次 I/O 和 512 字节的数据预算检查。
- 这些是主机模拟 SD 检查，不能替代真实 SD 卡的掉电、总线延迟及设备内存验收。

## 默认日志降噪

默认固件不输出成功的内存分配、整数设置读取、正常 LXMF 接收统计、Wi-Fi 接收周期统计以及邮资计算中间进度。Wi-Fi 接收队列丢包仍每分钟汇总；LXMF 解析失败保留原统计周期的摘要。屏幕电源只输出实际状态变化或产生显示动作的事件，不重复打印无效果的输入事件。

内存准入拒绝、分配失败、连接异常、Geocaching 目录发现与响应、会话状态仍保留。排查底层收发时可在编译参数中设置 `-DTRAIL_MATE_VERBOSE_RUNTIME_LOGS=1`，恢复上述详细统计。此开关仅控制日志，不改变接收预算、队列处理、内存释放或投递策略；目录请求误走传播节点的问题需另行修复。
