索引路径现已在主机模拟 SD 上通过实际 `DownloadClient → SdDownloadPort → IndexedDownloadStore` 链路验证：

- 创建耐久下载任务、等待响应、来源匹配及签名/摘要核对；回调返回后覆盖原响应缓冲仍能完成安装。

## 设备启动恢复接入（2026-09-24）

`browse_runtime.cpp` 的启动恢复现已纳入当前安装代次的已完成任务，不再因 `Task.state == 3` 跳过 Installed 后的历史保留。使用 48 字节请求键作为恢复游标，避免按账本偏移跨提交续读，也避免每次从头选中同一条已完成记录。若已经安装的 GPX 被外部修改或历史文件缺失，保留文件并提示问题，继续浏览其他缓存；尚未完成的安装失败及存储需要重放仍会阻止启动完成。

`DownloadClient::resume` 接收端口准备状态，在异步读取完成前保持 Pending 并拒绝接收下载响应。预览名称在调用时复制，原借用缓冲可以释放；该过程不会新建任务或重发请求。设备等待下载恢复调用已使用此接口。

`SdIndexedDownloadRecovery` 实现同一恢复资格规则的分步索引扫描，借用共享根与帧，仅保留当前/候选请求元数据，不加载任务列表。它尚未装配到设备 Session，但已用于索引恢复集成测试：测试从模拟 SD 重建根后自行查找请求/任务，然后创建实际下载端口恢复安装，不再预先把快照中的任务 ID 传给端口。

新增验证覆盖：

- 当前代次的 Installed 任务能被启动选择器找回，旧代次、取消任务和停止意图不作为安装任务恢复。
- 无序请求列表按稳定键恢复；安装提交改变编码行长度后，下一次选择不会重复或跳过任务。
- 索引工作区争用时恢复保持 Pending；读取完成后才转为等待网络，日志序号和磁盘字节保持不变。

## 发布适配器的索引集成验证（2026-09-24）

`PublicationStore` 将现有 `SdAuthorIssuePort` 和 `SdPublishPort` 从具体旧账本存储类中解耦。`IndexedPublicationStore` 使用同一个索引根及 `IndexWorkspaceOwner`；`SdIndexedAuthorReservation` 将版本预留和草稿冻结放入同一提交，发布回执复用索引目录响应提交器更新任务与请求。

主机模拟 SD 测试现已实际执行 `AuthorIssue → SdAuthorIssuePort → IndexedPublicationStore` 和 `PublishAttempt → SdPublishPort → IndexedPublicationStore`，覆盖：

- 未绑定草稿的作者绑定、过期代数拒绝、相同作者重复绑定不写日志。
- 共享工作区争用时签名任务保持等待，其他 owner 的租约不被夺取。
- 版本预留与草稿 base hash / generation 原子更新，提交验证完成后才调用签名接口；相同版本重试不再写入，过期草稿不能重新预留。
- 发布请求在调用返回后覆盖输入缓冲，仍可完成耐久任务提交；错误来源的回执被拒绝。
- 正确回执在回调返回后覆盖原缓冲，仍可完成确认；重复提交同一回执不增加日志。
- 等待发布的取消遇到 Busy 时持续等待，租约释放后完成停止事务。
- 在版本预留时注入 flush 失败，签名接口调用次数为零，根不前进，存储要求恢复。

签名传输使用固定的真实签名样本替身；测试证明持久化与调用顺序，不证明设备私钥签名、无线发送或真实目录服务可用。这里仍是设备主路径切换的前置验证：设备 Session 尚未装配索引发布适配器，多目录恢复、后继版本和完整掉电矩阵仍需补齐。不能将本节视为设备存储迁移已完成。

## 设备草稿入口解除同步账本读取（2026-09-24）

设备 `Facade::readDraft`、`Facade::saveDraft` 及后台草稿读写分支现已通过存储契约访问记录，不再自行调用 `LogicalState::view().find()`。读取由后台完成，只复制当前一条草稿的编码结果供 UI 同步消费；UI 回调不再借用随后可能被提交替换的账本内存。取消或改读另一条草稿时，由后台释放存储读租约。

保存命令只携带可编辑字段和期望代数。`restoreDraftIdentity` 在验证代数后，从已提交记录补回作者及版本 base hash，使用 101 字节前缀与原地移动保留文本，无需第二份完整草稿。旧存储和索引存储共用此规则，后者仍执行“已签名请求必须保留”的编辑约束。设备任务保留输入直到 `inputConsumed()` 或终态；Busy 时允许当前存储操作继续推进，不占住后台循环。

`IndexedPublicationStore` 新增可等待草稿读取，Ready 保持租约直到消费后显式释放；读取缓冲不足单独返回 `WorkspaceTooSmall`，不将其标记为账本损坏。新增主机用例覆盖读租约争用、读取消、读取结果复制后继续提交、作者与 base hash 保留、过期编辑拒绝及小帧读取失败。旧存储路径也验证同一编辑契约，避免设备在整体切换前出现行为回退。

验证结果：Geocaching 主机全量 75 项通过；ESP 栈检查及 `git diff --check` 通过。Pager `tlora_pager_lr1121` 构建以 0 退出并报告 SUCCESS（139.97 秒）；静态 RAM 100,344 字节，Flash 4,397,169 字节，日志 `.codex-build/logs/geocaching-pager-draft-io.log`。GitNexus 变更检查识别 12 个已跟踪文件、79 个符号，风险 LOW；新文件不在此图谱覆盖内。

此处完成的是实际设备草稿读写入口对同步账本查询的解耦。Session 仍创建 `LogicalState`；发布列表、发布前检查/版本重建、已下载目录和恢复入口仍有旧账本依赖，不能据此宣称两块 4 KiB 内存区已删除或实机迁移已完成。没有刷写、提交或推送。

## 发布列表与作者绑定主路径（2026-09-24）

设备 Published 列表现在通过后台读取固定四条元数据窗口，`Facade::snapshot`、`item` 和发布前检查不再直接扫描旧账本。UI 通过 `requestWindow` 提交可见偏移；页内容仅在 Ready 后可见，索引扫描期间共用工作区并固定根版本。切页、切走列表、启动前台操作或关闭会话时，由后台释放读租约。描述和提示用完整文本的 SHA-256 比较本地修改状态，不把截断后的显示文字当成版本内容。

`SdIndexedDraftCatalog` 分步读取草稿、发布请求和父任务，投影最新版本、确认版本、保留基线、待处理和停止状态。固定窗口不保存完整草稿文本，也不加载全量列表。主机用例覆盖九条草稿的多个窗口、偏移 3、空尾页、取消租约、仅修改描述/提示及每步传输不超过 512 字节；这些数据量检查不证明 SPI 或 flush 延迟上限。

## 恢复对象分配失败分类（2026-09-24）

重放验证器分配失败现在返回独立的 `IndexReplayStep::OutOfMemory`，由正常恢复层传递为 `IndexedRecoveryStep::OutOfMemory`。修复包装器只针对 RecoveryRequired 启动损坏重建，因此不会因该内存失败启动重建。包装器创建恢复器或清理器失败也返回 OutOfMemory；设备启动页面显示内存不足提示，释放本轮恢复对象，保留磁盘状态。

故障注入覆盖重放验证器和其内部引用校验器的实际 nothrow 分配。`SdIndexedCommit::begin` 在引用校验器分配失败时保存独立的 `IndexedCommitStep::OutOfMemory`，重放层读取并传递该终止结果。测试事务同时包含草稿、既有签发历史及请求关联，分别令第一个和第二个分配失败：返回明确终止状态、再次调用仍保持该状态、文件逐字节不变；后续创建新恢复对象可处理同一日志。

## 日志重放 I/O 分类补充验证（2026-09-24）

`SdIndexReplay` 现在保留业务校验和索引事务返回的 I/O 错误，返回独立的终止状态 `IoError`；`SdIndexedRecovery` 将其继续传递为 I/O 错误，避免 `SdIndexRepair` 因临时读写失败启动损坏重建。失败的重放对象不会继续消费事务，重试应创建新的恢复对象。

## 设备启动接入索引重建（2026-09-24）

设备 Session 已改用 `SdIndexRepair` 包装原有恢复流程。正常索引继续校验与回放；恢复判定需要修复时，将派生目录 `index` 保留为 `index.repair`，复用原有检查点导入和日志回放生成新索引。新索引通过逐表与引用校验后才清理备份并开放业务。重建失败保留备份、权威日志、检查点及 GPX；恢复器返回 IoError 或 VolumeChanged 时不启动重建。重启遇到已有备份时，先尝试继续新索引的正常恢复；部分生成文件损坏时，仅清理新建的派生树并再次重建。

恢复器累计有效根中的提交序号，并在清理部分新索引之前持久保存最低恢复序号。备份目录中的空文件名 `gcf1-<16位十六进制序号>-<8位CRC32>` 承载该水位，CRC 覆盖 volume_instance 与大端序号；文件创建、flush、重新读取确认后才继续。旧水位不被覆盖，文件内容撕裂不会把水位变成空值；重建序号低于水位时拒绝就绪。备份只有在新索引验证完成后才被回收。清理使用固定深度、单目录句柄和有界路径，仅接受既定根、槽、表、分片与水位名称，未知文件不删除。

本轮遵照用户要求减少编译：仅增量编译实际运行时测试目标并运行对应回归，没有例行重新构建 Pager，也没有重新编译 Linux ASan。新增代码已接入设备生产启动入口，但本轮主机结果不能替代最新固件构建或真实 SD 掉电测试。检查点来源重建、大记录与长期维护、真机网络、正式目录／桥接和网页交付仍需继续，未提交、推送或刷写。
